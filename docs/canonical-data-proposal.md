## Schema gaps resolved since the last review

Two issues the prior review flagged as blocking were resolved this pass — both in the schema itself, not worked around in the data:

1. **Role date precision.** `roles.start_date`/`end_date` (SQL `DATE`) were replaced in place with `start_year`/`start_month`/`end_year`/`end_month` integer columns, since no real data had been imported yet under the old shape. Application-level validation (a `saving` listener, same pattern as CareerFact's attribution check) rejects out-of-range months, an end month with no end year, and an end before the start. See `docs/domain-model.md` → "Role date precision".
2. **Metric ranges.** `career_fact_metrics` gained a nullable `value_max` column. `value` stays the primary/lower figure; `value_max` is set only for a genuine two-sided range and is never a fabricated midpoint. Application-level validation rejects `value_max < value`. See `docs/domain-model.md` → "Bounded ranges". The Marketing Budget & Forecast Hub fact now uses this directly (`value: 10, value_max: 15`).

## Claim boundaries preserved by this dataset

These are **authoring/tailoring boundaries, not negative CareerFacts** — this dataset does not, and should not, contain "does not have X" rows (consistent with "Unresolved competing claims stay as separate CareerFacts" in `docs/domain-model.md`: absence of evidence is represented by absence of a fact, never by an invented negative one). Nothing in this dataset currently evidences, and future edits should not casually introduce evidence for, any of the following unless a genuinely new, separately-confirmed source justifies it:

- Federal government, VA/Veterans Affairs, VHA, or healthcare experience of any kind.
- Section 508 program delivery or compliance work.
- Formal Microsoft 365 or SharePoint adoption/administration.
- LMS (learning management system) administration.
- Formal responsible-AI governance or AI policy development.
- Advanced graphic design, professional animation, or professional audio production.

**Adjacency is not equivalence** — several facts in this dataset are genuinely close to these boundaries, and future editors/tailoring reviewers should hold the line explicitly:

- Technical documentation (`rocketgate-developer-documentation-onboarding`) ≠ Section 508 expertise.
- RAG/AI development (Verbatim, `rocketgate-ai-assisted-knowledge-management`) ≠ responsible-AI governance.
- Developer/merchant onboarding enablement ≠ federal workforce training.
- CMS experience (Liquid Gravity) ≠ SharePoint experience.
- Video marketing/editing (Liquid Gravity, Brute Strength) ≠ advanced multimedia production.
